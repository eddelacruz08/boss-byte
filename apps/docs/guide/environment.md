# Environment variables

There are three `.env` files, each with a different job:

| File             | Read by                  | Created by                          |
| ---------------- | ------------------------ | ----------------------------------- |
| `apps/api/.env`  | The API, worker and CLIs | `npm run setup`                     |
| `apps/core/.env` | Vite (the dashboard)     | `npm run setup`                     |
| `.env` (root)    | Docker Compose only      | You, from `.env.example`, if needed |

`npm run setup` copies each app's `.env.example`, generates the JWT key pair and fills in the
secrets that must be random. It never overwrites a value you have set. Pass `-- --force` to
regenerate the JWT key pair and `CSRF_SECRET`, which signs every user out; the encryption keys
are never regenerated that way, because that would make existing data unreadable.

## API (`apps/api/.env`)

The API validates its environment with Zod on start-up (`apps/api/src/config/env.ts`). If a
required variable is missing or malformed it prints every problem and exits with code 1. Variables
already present in the real environment win over the file, and the file is not read at all when
`NODE_ENV=test`.

### Server

| Variable       | Default                 | Notes                                                                                        |
| -------------- | ----------------------- | -------------------------------------------------------------------------------------------- |
| `NODE_ENV`     | `development`           | `development`, `test` or `production`                                                        |
| `PORT`         | `4000`                  |                                                                                              |
| `LOG_LEVEL`    | `info`                  | Pino level. Logging is silent under test                                                     |
| `APP_NAME`     | `BossByte`              | Used in emails and as the TOTP issuer                                                        |
| `APP_URL`      | `http://localhost:5173` | Public URL of the dashboard. Its origin is allowed by CORS and expected by WebAuthn          |
| `CORS_ORIGINS` | empty                   | Extra allowed origins, comma-separated                                                       |
| `TRUST_PROXY`  | `0`                     | Number of reverse proxies in front of the API. Needed for correct client IPs and rate limits |

### Data stores

| Variable            | Default | Notes                                                                                    |
| ------------------- | ------- | ---------------------------------------------------------------------------------------- |
| `DATABASE_URL`      | —       | **Required.** PostgreSQL connection string                                               |
| `DATABASE_POOL_MAX` | `10`    | Connections per process                                                                  |
| `DATABASE_SSL`      | `false` | Set to `true` for managed databases that need TLS                                        |
| `REDIS_URL`         | —       | **Required.** Used for cache, rate limits, lockouts, WebAuthn challenges and Bull queues |

### Tokens, cookies and CSRF

| Variable               | Default                  | Notes                                                                  |
| ---------------------- | ------------------------ | ---------------------------------------------------------------------- |
| `JWT_PRIVATE_KEY_PATH` | `./keys/jwt-private.pem` | RS256 private key file                                                 |
| `JWT_PUBLIC_KEY_PATH`  | `./keys/jwt-public.pem`  | RS256 public key file                                                  |
| `JWT_PRIVATE_KEY`      | —                        | Base64-encoded PEM. Overrides the path; use it where files are awkward |
| `JWT_PUBLIC_KEY`       | —                        | Base64-encoded PEM. Overrides the path                                 |
| `JWT_ISSUER`           | `bossbyte-api`           |                                                                        |
| `JWT_AUDIENCE`         | `bossbyte`               |                                                                        |
| `CSRF_SECRET`          | —                        | **Required**, at least 32 characters. Generated by setup               |
| `COOKIE_SAME_SITE`     | `lax`                    | `lax`, `strict` or `none`. `none` forces `Secure` cookies              |

To produce the base64 form of a key:

```bash
base64 < apps/api/keys/jwt-private.pem | tr -d '\n'
```

### Rate limits

| Variable                | Default | Notes                                                                    |
| ----------------------- | ------- | ------------------------------------------------------------------------ |
| `RATE_LIMIT_GLOBAL_MAX` | `300`   | Requests per minute per address, across the whole API                    |
| `RATE_LIMIT_AUTH_MAX`   | `20`    | Requests per 15 minutes per address on endpoints that accept credentials |

Leave both empty to use the defaults from `SECURITY.rateLimit` in `@bossbyte/shared`. See
[Security](/api/security#rate-limiting).

### Encryption at rest

| Variable                        | Default | Notes                                                                         |
| ------------------------------- | ------- | ----------------------------------------------------------------------------- |
| `DATA_ENCRYPTION_KEY`           | —       | **Required.** Base64 of 32 random bytes. Encrypts new data                    |
| `DATA_ENCRYPTION_PREVIOUS_KEYS` | empty   | Comma-separated retired keys, still accepted for decryption during rotation   |
| `BLIND_INDEX_KEY`               | —       | **Required.** Base64 key for the HMAC blind indexes. Never rotate it casually |

See [Encryption](/api/encryption) for how to generate and rotate these.

| `S3_ENDPOINT`          | —           | Leave unset for AWS. `http://localhost:9000` for the local MinIO                 |
| `S3_PUBLIC_ENDPOINT`   | —           | Endpoint used only when signing URLs, when browsers reach the bucket differently |
| `S3_REGION`            | `us-east-1` |                                                                                  |

| `GCS_BUCKET`           | —           | Required when `STORAGE_DRIVER=gcs`                                               |
| `GCS_PROJECT_ID`       | —           | Optional; Application Default Credentials usually supply it                      |

## Dashboard (`apps/core/.env`)

Only variables starting with `VITE_` reach the browser, and they are baked in at build time.
Every one is optional in development.

| Variable                    | Default                 | Notes                                                                         |
| --------------------------- | ----------------------- | ----------------------------------------------------------------------------- |
| `VITE_API_URL`              | `/api/v1`               | API base URL as the browser sees it. Same-origin by default                   |
| `VITE_API_PROXY_TARGET`     | `http://localhost:4000` | Where the Vite dev server forwards `/api` requests                            |
| `VITE_FIREBASE_API_KEY`     | —                       | The Google button appears only when all four `VITE_FIREBASE_*` values are set |
| `VITE_FIREBASE_AUTH_DOMAIN` | —                       |                                                                               |
| `VITE_FIREBASE_PROJECT_ID`  | —                       |                                                                               |
| `VITE_FIREBASE_APP_ID`      | —                       |                                                                               |

Keeping `VITE_API_URL` same-origin is what makes the refresh cookie work without any cross-site
cookie configuration: Vite proxies `/api` in development and nginx does the same in the Docker
image.

## Docker Compose (root `.env`)

The root `.env` only moves host ports and swaps images for `docker-compose.yml`. You need it only
when a default port is taken.

| Variable             | Default                                      |
| -------------------- | -------------------------------------------- |
| `POSTGRES_PORT`      | `5432`                                       |
| `REDIS_PORT`         | `6379`                                       |
| `MINIO_PORT`         | `9000`                                       |
| `MINIO_CONSOLE_PORT` | `9001`                                       |
| `MAILPIT_SMTP_PORT`  | `1025`                                       |
| `MAILPIT_UI_PORT`    | `8025`                                       |
| `PGADMIN_PORT`       | `5050`                                       |
| `API_PORT`           | `4000` (the `app` profile)                   |
| `CORE_PORT`          | `8080` (the `app` profile)                   |
| `MINIO_IMAGE`        | `cgr.dev/chainguard/minio:latest-dev`        |
| `MINIO_MC_IMAGE`     | `cgr.dev/chainguard/minio-client:latest-dev` |

After changing a port, run `npm run setup` again. It rewrites the matching URLs in
`apps/api/.env` so the API follows the move.
