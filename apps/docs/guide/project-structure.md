# Project structure

```text
boss-byte/
├── apps/
│   ├── api/                  @bossbyte/api — Express API and Bull worker
│   ├── core/                 @bossbyte/core — React dashboard
│   └── docs/                 @bossbyte/docs — this site
├── packages/
│   ├── shared/               @bossbyte/shared — schemas, types, constants, helpers
│   └── ui/                   @bossbyte/ui — React components and hooks
├── docker/                   Dockerfiles, nginx config, PostgreSQL init script
├── e2e/                      Playwright tests
├── scripts/                  setup, licence check, version stamping
├── .github/                  CI, CodeQL, release and deploy workflows, Dependabot
├── docker-compose.yml        Local services, plus the full stack behind a profile
├── ecosystem.config.cjs      PM2 process definitions
├── turbo.json                Task pipeline
├── tsconfig.base.json        Compiler options every workspace extends
├── eslint.config.js          One flat ESLint config for the whole repo
└── knip.json                 Unused-code check configuration
```

## The API (`apps/api`)

```text
apps/api/
├── migrations/               Hand-written SQL, applied in filename order
├── keys/                     Local RS256 key pair (generated, git-ignored)
├── src/
│   ├── server.ts             HTTP entry point
│   ├── worker.ts             Background worker entry point
│   ├── app.ts                createApp(): middleware and routers, in order
│   ├── config/               env.ts (validated environment), keys.ts (JWT keys)
│   ├── db/                   client, schema, migrate, seed, encryption, rotate-keys
│   ├── docs/openapi.ts       OpenAPI 3.1 document built from the shared schemas
│   ├── jobs/                 queues.ts and processors/
│   ├── lib/                  audit, crypto, documents, errors, firebase, logger,
│   │                         mailer, redis, shutdown, storage, uploads, validate,
│   │                         valuation
│   ├── middleware/           authenticate, csrf, error-handler, rate-limit
│   ├── modules/              auth, users, files, reports, valuation, health
│   └── types/express.d.ts    Adds `req.auth` to Express's Request
├── tests/
│   ├── defaults.ts           Test database and Redis URLs, and the safety check
│   ├── setup.ts              Unit test environment
│   └── integration/          *.int.test.ts, helpers and setup
├── tsdown.config.ts          Bundles five entry points into dist/
├── vitest.config.ts          Unit tests
└── vitest.int.config.ts      Integration tests
```

A module is a folder under `src/modules` with a `*.routes.ts` file (HTTP: parse, authorize, call,
respond) and a `*.service.ts` file (the work: queries and rules, no `req` or `res`). Anything two
modules need lives in `src/lib`.

The build produces one file per entry point: `dist/server.js`, `dist/worker.js`,
`dist/migrate.js`, `dist/seed.js` and `dist/rotate-keys.js`. `@bossbyte/shared` is bundled in;
everything else stays in `node_modules`.

## The dashboard (`apps/core`)

```text
apps/core/src/
├── main.tsx                  Configures Zod, then loads bootstrap.tsx
├── bootstrap.tsx             Mounts the router and the query client
├── router.tsx                createRouter() with the auth store in context
├── routeTree.gen.ts          Generated by the TanStack Router plugin — do not edit
├── routes/                   File-based routes
│   ├── __root.tsx            ToastProvider and devtools
│   ├── login.tsx, register.tsx
│   ├── _authenticated.tsx    Session guard and the app shell
│   └── _authenticated/       index, users, files, map, valuation, reports, settings
├── features/                 Per-feature API calls, query options and components
├── components/               App-level pieces: AppShell, charts, RequirePermission, …
├── lib/                      api, auth, query-client, forms, exports, download,
│                             sanitize, firebase, webauthn, redirect
├── data/sample-properties.ts Fictional sales that drive the map and valuation pages
└── styles.css                Tailwind and the UI package's stylesheet
```

See the [frontend overview](/frontend/overview).

## Shared packages

```text
packages/shared/src/
├── constants/                roles.ts, permissions.ts, security.ts
├── schemas/                  auth, user, file, report, valuation, common
└── utils/                    async, collection, format, misc, permissions, string

packages/ui/src/
├── components/               One file per component, with its test beside it
├── hooks/                    useDisclosure, useDebounce, useLocalStorage, …
├── lib/                      cn, date helpers, paginationRange
├── styles.css                Theme tokens and third-party styles
└── index.ts                  The public surface
```

Neither package has a build step. Their `package.json` `exports` point at TypeScript source, and
whichever app imports them compiles them. See
[Conventions](/guide/conventions#internal-packages-are-just-in-time).

## Root tooling

| File or folder               | Purpose                                                                 |
| ---------------------------- | ----------------------------------------------------------------------- |
| `scripts/setup.mjs`          | Creates `.env` files, JWT keys and secrets. Run through `npm run setup` |
| `scripts/check-licenses.mjs` | Fails when a dependency's licence is not on the allow-list              |
| `scripts/stamp-version.mjs`  | Writes one version into every `package.json` and the lockfile           |
| `docker/api.Dockerfile`      | One image for the API, the worker and the migration job                 |
| `docker/core.Dockerfile`     | Builds the dashboard and serves it with nginx                           |
| `docker/nginx/`              | nginx template and security headers for the dashboard image             |
| `docker/postgres/init/`      | Creates the `bossbyte_test` database on first start                     |
| `.github/actions/setup`      | Composite action: Node from `.nvmrc`, pinned npm, `npm ci`              |
| `.github/workflows/`         | `ci`, `codeql`, `e2e`, `release`, `deploy-dev`                          |
