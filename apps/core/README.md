# @bossbyte/core

The BossByte dashboard: React 19, Vite 8, TanStack Router (file-based) and Query, Tailwind CSS 4
and the `@bossbyte/ui` components. It talks to `@bossbyte/api`.

## Run it

From the repository root, with the API running on port 4000:

```sh
npm run dev -w @bossbyte/core        # http://localhost:5173, proxies /api to the API
npm run test -w @bossbyte/core       # Vitest, no backend needed
npm run typecheck -w @bossbyte/core
npm run lint -w @bossbyte/core
npm run build -w @bossbyte/core      # production build in dist/
```

Sign in with a seeded account, for example `admin@bossbyte.local` / `BossByte-Dev-2026`.

## Environment

`npm run setup` copies `.env.example` to `.env`. Every value is optional in development.

| Variable                | Default                 | Purpose                                           |
| ----------------------- | ----------------------- | ------------------------------------------------- |
| `VITE_API_URL`          | `/api/v1`               | API base URL as the browser sees it               |
| `VITE_API_PROXY_TARGET` | `http://localhost:4000` | Where the dev server forwards `/api`              |
| `VITE_FIREBASE_*`       | empty                   | Google sign-in; the button shows when all are set |

## Layout

```
src/
  routes/        One file per page. _authenticated.tsx guards everything under it.
  features/      API calls, query options and forms, grouped by feature.
  components/    App-level pieces: shell, page header, charts, error states.
  lib/           Reusable helpers with no knowledge of any one page.
  data/          The sample properties behind the map and valuation pages.
  test/          Test helpers: fetch mock, axe, fixtures, render with Query.
```

`src/routeTree.gen.ts` is generated by the router plugin on `dev` and `build`. It is committed so
type checking works on a fresh clone; do not edit it by hand.

## How sign-in works

- The access token is kept in memory only. The refresh token is an httpOnly cookie the browser
  sends to `/api/v1/auth`.
- On load, the app calls `POST /auth/refresh` to restore the session. A 401 there means signed out.
- A 401 on any other call triggers one shared refresh and one retry. If the refresh fails, the
  user is signed out and sent to `/login` with a `redirect` back to where they were.
- Requests without a Bearer header that change state (sign-in, refresh, sign-out) carry an
  `x-csrf-token` header. The client fetches the token on first use.

All of this lives in `src/lib/api.ts` and `src/lib/auth.ts`. Pages never touch tokens.

## Helpers worth copying

| File                           | What it gives you                                                     |
| ------------------------------ | --------------------------------------------------------------------- |
| `lib/api.ts`                   | `api.get/post/patch/delete/upload/download`, `ApiError`, `isApiError` |
| `lib/auth.ts`                  | `useAuth()`, `useCurrentUser()`, the `authStore` behind them          |
| `lib/exports.ts`               | `exportTableToPdf`, `exportTableToXlsx` for any array of rows         |
| `lib/download.ts`              | `saveBlob`, `startDownload`                                           |
| `lib/forms.ts`                 | `applyApiFieldErrors` maps API validation errors onto form fields     |
| `lib/sanitize.ts`              | `sanitizeHtml` for anything rendered from user-written HTML           |
| `lib/redirect.ts`              | `safeRedirectPath` rejects redirects that leave the app               |
| `lib/use-debounced-input.ts`   | A text input that commits its value after a pause                     |
| `components/RequirePermission` | Renders children only for roles that hold a permission                |

Each one has a short example in its JSDoc.

## Adding a page

1. Create `src/routes/_authenticated/invoices.tsx` and export `Route = createFileRoute(...)`. The
   route tree regenerates while the dev server runs.
2. Put the API calls and `queryOptions` in `src/features/invoices/api.ts`, typed with the schemas
   from `@bossbyte/shared`.
3. Add the page to the `NAV_ITEMS` list in `src/components/AppShell.tsx`, with the permission it
   needs, so it only shows for roles that can use it.

## Bundle

Routes are split automatically. The heavy libraries load only when used: Leaflet with the map
page, Chart.js with the first chart, the rich-text editor with the reports page, jsPDF and exceljs
when an export button is pressed, Firebase when Google sign-in is pressed.

## End-to-end tests

Playwright specs live in `e2e/` at the repository root and run against the real API and database:

```sh
npm run docker:up && npm run db:migrate && npm run db:seed
npx playwright install chromium   # first time only
npm run test:e2e
```
